# PC 控制台架构说明

## 设计边界

控制台运行在 PC，而不是 AGX。浏览器无法直接使用原生 TCP、UDP 或 RTSP，因此采用“浏览器 UI + PC 本地桥接服务”两层结构。

```text
┌────────────────── PC ──────────────────┐
│                                        │
│  Browser UI                            │
│  http://localhost:3000                 │
│     │ HTTP + SSE + HLS                 │
│     ▼                                  │
│  Local Bridge                          │
│  http://127.0.0.1:4100                 │
│     ├── TCP/UDP command ───────────────┼──► AGX
│     ├── UDP heartbeat ─────────────────┼──► AGX
│     ├── UDP telemetry ◄────────────────┼─── AGX
│     └── RTSP ◄── FFmpeg remux ─────────┼─── AGX
│                                        │
└────────────────────────────────────────┘
```

## 通信映射

| 数据方向 | PC 接口 | AGX 接口 | 说明 |
|---|---|---|---|
| UI → Bridge | `POST /api/command` | TCP 8080 或 UDP 14551 | 桥接服务生成 30 字节小端控制包 |
| Bridge → AGX | UDP 14551 | UDP 14551 | 每秒发送 JSON 心跳 |
| AGX → Bridge | UDP 14550 | PC UDP 14550 | 接收快包和慢包 JSON，并合并为完整状态 |
| UI ← Bridge | SSE `/api/events` | — | 推送遥测、链路状态和事件日志 |
| AGX → UI | RTSP 8554 → HLS | `/m350/fpv` | FFmpeg 仅重新封装，不重新编码 |

快遥测包只有位置和时间，慢遥测包包含姿态、电池、云台和导航。本地桥接采用字段合并，收到快包时不会清空最近一次慢包字段。

## 飞行安全设计

- 本地桥接只监听 `127.0.0.1`，不会直接暴露到局域网。
- 浏览器跨域访问只允许配置的本地 UI Origin。
- 航点、高度和云台参数在组包前进行范围校验。
- TCP 控制使用持久连接，避免 AGX 将短连接断开误判为控制端失联。
- 起飞、降落、返航、强制降落、清空任务和切换航点需要二次确认。
- UI 明确区分“网络写入成功”和“飞行动作已完成”。当前 AGX 协议没有 ACK，动作完成以遥测为准。

## 本地桥接 API

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/api/status` | 获取配置、遥测、TCP、视频和 FFmpeg 状态 |
| `GET` | `/api/events` | SSE 实时状态、遥测和日志 |
| `POST` | `/api/command` | 下发控制命令 |
| `PUT` | `/api/config` | 保存配置并重建通信链路 |
| `POST` | `/api/video/restart` | 手动重启 RTSP→HLS 桥接 |
| `GET` | `/stream/index.m3u8` | 浏览器直播播放列表 |

## 后续建议

1. AGX 控制协议增加命令序号、ACK、执行状态和幂等控制。
2. 增加双向身份认证、报文签名和重放保护。
3. 视频由 HLS 升级为 WebRTC，将 PC 端显示延迟从约 2～4 秒降到亚秒级。
4. 引入离线地图与禁飞区/距离边界校验，再开放图上选点。
5. 增加飞行前检查清单和基于遥测状态的按钮互锁。
